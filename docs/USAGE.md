# 使用與動畫規格

## 第一次使用

提供角色圖片與動作描述即可。首次提出最終成品128×128、播放1秒，8fps為初始輸出預設；取幀時依實際動作在4-16fps間調整。先問是否採用；若選否，只需提供最終尺寸與播放長度，不要求填fps。已提供的資訊不重問。若需要超過16fps，必須說明原因並取得同意，最高24fps。

來源影片只詢問解析度，以編號選擇：

1. **效能：512×512**
2. **平衡：768×768（預設推薦）**
3. **品質：1024×1024**

這三檔不依成品尺寸乘倍率放大。選定後依完整動作範圍安排位置與留白，並檢查工作流相容性；不默默改解析度或縮小單一動作。來源固定24fps，不詢問來源秒數及影格數。由Codex依最終播放時間的2-3倍評估來源長度，預設3倍，請求與實際時長皆不超過15秒。

來源較長是為取得2-3次完整動作，最後只選一組。完整性優先於次數；15秒上限可能減少比較機會，生成後要如實回報實際完整組數。來源依17k+5影格規則對齊，上限345幀、14.375秒；不能向上對齊為362幀而超過15秒。

## 生成前摘要與沿用

每次提交生成前，即使是同一對話的新任務，也要分段列出**最終成品**與**AI來源影片**的本次實際設定。摘要格式固定，數值依當次選擇與計算填入，不寫死：

- **最終成品**：成品尺寸、預設8fps、播放秒數；說明4-16fps動態評估、超過16先詢問，以及透明PNG、圖集與GIF預覽。
- 角色預設置中，依完整動作範圍調整位置與留白，確保本體及所有附屬部份完整入鏡；交付保留相同構圖。
- **AI來源影片**：選定的尺寸與方案、固定24fps、確切請求秒數，另列對齊後的影格數與實際長度；不顯示尚未選定的時長範圍。

同一對話的新任務可默認沿用已接受設定，不必重複詢問，但摘要不能省略。來源秒數依新任務自動評估並列明；成品尺寸、播放秒數與來源解析度不默默更改。不同對話使用舊設定時，先確認是否適用。設定存在專案自己的 `.comfyui-sprite-forge.preferences.local.json`，不提交Git。

最終fps不是來源fps，也不等於所有動畫的總幀數。總幀數為播放秒數×fps；取幀後交付標示實際fps及影格數，並保留必要轉折和刻意停留時間。增加輸出fps不能修復來源動作錯誤或裁切。

規格工具不需網路或GPU。寬高需對齊32並符合實際工作流限制；來源24fps與固定對齊規則不能另改。硬體有限時先選較低來源解析度，不能只由顯存容量保證可執行。

## 動作參考與畫面規劃

本專案只內建本機ComfyUI圖生影片。原角色圖與動作姿勢差距很大時，先評估動作專用首幀；可用另行授權的可用圖片工具，或使用者提供的圖片，草圖不是必需。新首幀先展示確認，再生成影片，不會自行使用雲端API key。

在來源四周依完整動作預留空間，保留原角色的頭身比、四肢與服裝。不同動畫使用共同角色尺度與相容基準點，不能逐格依外框縮放。位移由遊戲控制時去掉非預期整體漂移，但保留姿勢變化與合理微動；不能一律鎖腳底或質心。來源裁掉的肢體無法靠補透明畫布救回。

規格與交付的完整操作見 [規格引導](../skills/comfyui-forge-video2dsprite/references/specification-guide.md)，視覺規劃見 [動作規劃與驗收](../skills/comfyui-forge-video2dsprite/references/motion-planning.md)。

## 調整告知與重試決策

來源裁切需重生時，先告知被裁切的部份、方向，以及位置和留白調整，再直接執行；若來源完整、只是後製裁切，沿用來源修正，不重生。移動後重新檢查所有方向。最終取幀前也先告知評估的fps、總幀數、理由及保留的播放長度；4-16fps告知後直接執行，超過16fps須等待同意，最高24fps。

同一項要求在連續兩次已完成、已檢視的生成中出現相同偏差時，暫停第三次提交。回報具體偏差、違反的要求及兩次之間改過什麼，並說明「依目前結果推測，再次重送大概率仍可能發生」。這不是認定做不到，而是讓使用者選擇：1放寬該項條件；2維持原要求、繼續嘗試。選擇前不提交，也不自行放寬。

選擇堅持後，保留原驗收標準並告知下一次的調整。修改提示詞、變更種子都算不同嘗試方法，可以搭配使用，不要求每次更換構圖或參考圖。新生成有新種子；續取任務保留既有種子。單段來源內的重複演示、輪詢或續取不算兩次生成；單純改種子或提示也不抹去前兩次相同偏差的觀察。此規則適用所有動作，且優先於一般構圖調整可直接重送的授權。

## 標準交付

圖集依總幀數排版：4、6幀單列，8幀以上雙列（欄數為總幀數除2向上取整），由左至右、由上至下播放；尾端空格不算動畫影格。

對話中依序提供：

1. **ZIP下載**：僅包含整理後、已選定的透明PNG影格、透明PNG Animation Frame Sheet、GIF預覽及原始來源MP4。
2. 顯示GIF預覽。
3. 顯示Animation Frame Sheet，附每格尺寸、總格數、欄列、讀取順序、基準時間/fps與播放方式。
4. 顯示／提供來源影片。
5. 「其它中間處理檔，如：JSON、日誌、檢查報告與未選影格…等，都留在[工作目錄]，不放進標準交付 ZIP。」工作目錄文字加上實際完整路徑連結。

以上所有說明會跟隨使用者語言，並非限定中文。單次動作的GIF可以重複展示方便預覽，並註明遊戲素材仍是單次動作。GIF使用10ms時間單位及二值透明；必要時回報時間近似，PNG保留完整透明度。事件資料與精確時間留在工作紀錄，重要事件影格也列於對話。

本修改版不提供額外引擎JSON、APNG、WebM或瀏覽器runtime；只維護標準PNG影格、圖集、GIF及來源MP4交付。原始影片與工作影格保留以供續取、驗證或重新選格。

## 工具與中斷處理

1. `comfyui_forge_animation_spec.py`：計算／確認／保存規格；`--help`列出plan、save、show。
2. `comfyui_forge_prepare_i2v_input.py prepare`：用確認的來源尺寸準備等比例角色、留白、key背景與registration_job；先觀看input.png。
3. `comfyui_forge_route_media.py video --route comfyui`：用確認的來源秒數提交一次本機任務；fps來自匹配的工作流設定。
4. `comfyui_forge_video2dsprite.py process`、`comfyui_forge_register_clip.py apply`：去背、解碼與定位，檢查亮暗底與漂移。
5. `comfyui_forge_gait_loop.py`／`comfyui_forge_retime.py`：分析完整候選動作並依動作結構選格、安排重要姿勢與事件；不是平均切整段影片。若採往返微動，先整理完整播放順序，不能直接倒播跑步或有固定事件順序的動作。
6. `comfyui_forge_finish_frames.py`：共同比例縮放到最終尺寸，準備剛好所需格數的播放序列。
7. `comfyui_forge_deliver_animation.py`：不再縮放或選格，驗證尺寸／格數並輸出乾淨成品與ZIP。使用確認的設定檔，`--report`指向工作目錄。

pending：續取原生成資料夾，不重送。unknown：先看本機queue/history與job.json。done：校驗SHA256並重用影片。只改最終格數、時間、輸出格式時，優先使用已有影片，不為了驗證安裝重複生成。
