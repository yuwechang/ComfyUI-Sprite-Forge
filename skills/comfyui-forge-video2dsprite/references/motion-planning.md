# Plan the requested motion

Choose cycle, oneshot-return or oneshot-hold from intended gameplay behavior. Describe actual facing, pose, expression, local movement, support constraints, attachments and motion envelope without selecting a named template. Confirm only consequential ambiguity. A first frame does not guarantee the generated movement.

Plan margins for the full silhouette and intended translation at a shared scale. Decide whether the engine or animation owns world movement. Do not shrink, stretch or crop one motion to hide inadequate clearance. Prepare separate phases/references only when the request needs them. Automatic registration padding can extend a logical canvas once; it cannot restore clipped video pixels.

Source2-3 repetitions provide selection opportunities for all three types. They are not a longer single action or a combination of unrelated movements. Compare full independent candidates; retain one complete instance including its correct ending. A continuous period matches moving phase, a returning action completes recovery, and a held-ending action retains its terminal state. If repeat count compromises completeness, propose more source time.

Try flat-background extraction independently of motion type. Preserve true alpha. Estimate arbitrary solid input colour from four edges, check consistency and the resulting matte, then compare generation keys against subject colours. Continue if successful; stop for a user-corrected image only if extraction/quality fails. Never use colour locking to disguise alpha loss. Review output transparency on light/dark backgrounds.

Choose timing after candidate review. Cycles usually need phase selection; one-shots normally need retime. Explicit key poses, holds and events follow the request and observed source, not an action label. Keep original sequence order and preserve intended initial/terminal state. Review the final-size materialized result before acceptance.
